Editing rpt.conf for Private Nodes

How the Config tab adds and removes private nodes (numbers 1000 to 1999) in Asterisk's rpt.conf, and in the other files that go with them: extensions.conf, modules.conf and allmon3.ini. It covers the preview, the automatic copies, the managed blocks it leaves alone, and what it does not restart.

Part 1 · What is changed

The files and the card

The Config tab's Add private node card changes up to four files. It never edits a file it does not own, and it never restarts Asterisk.

FileChange
/etc/asterisk/rpt.confA new node stanza, and the node's line in the [nodes] section.
/etc/asterisk/extensions.confAn exten line in the [radio-secure] context, if that context exists (optional, ticked on the card).
/etc/asterisk/modules.confOnly for a USRP bridge node: chan_usrp is set to load.
/etc/allmon3/allmon3.iniA section for the node, with its host, port, user and password copied from a public node section, so Allmon3 can show it.

1.1The rules of the card

  • It adds only nodes between 1000 and 1999 (_CFGR_PRIVATE_MIN and _CFGR_PRIVATE_MAX).
  • It never adds or removes the reserved numbers 1917 (the M17 bridge), 1921 (Node Talker's transmit node) or 1999 (the digital bridge). A node number 1921 is pointed to Node Talker's TX card.
  • It removes only nodes it added. A node written by hand, or by the Dashboard's Phone tab, is left alone.
  • It does not restart Asterisk. The result says "Asterisk was NOT restarted", and the operator uses the ASL3 Restart button when ready.
Part 2 · The steps

Preview, then add

Every change has two steps: a preview that writes nothing, and an apply that writes the files. The card uses the same code for both. The preview shows the diff of each file that would change.

2.1Choosing the number

A blank number means the next free one. The helper scans rpt.conf for every section name and every number in the [nodes] section, then picks the first number from 1000 upward that is not used and not reserved. If none is free, the card says so. A number typed by hand must be 1000 to 1999, and must not already be in rpt.conf.

2.2Plain node or USRP bridge

KindrxchannelExtra settings
PlainLocal/pseudoNone
USRP bridgeUSRP/127.0.0.1:<tx>:<rx>, from the two ports the card asks forThe bridge profile: duplex 0, hangtime 0, althangtime 0, holdofftelem 1, telemdefault 0, telemdynamic 0, linktolink no, nounkeyct 1, tx_timeout 170000. chan_usrp is set to load in modules.conf.

For a USRP node, the two ports must differ, and neither can already be used by another USRP node in rpt.conf. The card reports any other clash as a warning (port clash check).

2.3The stanza that is written

The stanza is headed by a note line, ; 44helper: private node added on the Config tab (remove it there), which is how the card recognises its own nodes later. The header takes its template from the main node's stanza, found by the node's own number in the identity settings (or the first public node). For example, if the main node is [652701](node-main), the new node gets [1000](node-main). If there is no template, the node is written with no template, and the card says so.

; 44helper: private node added on the Config tab (remove it there)
[1000](node-main)
rxchannel = Local/pseudo

The [nodes] line for the node uses the local IAX port from the config. On port 4569 it is 1000 = radio@127.0.0.1/1000,NONE. On another port, the port is written after the address.

2.4The exten line

If [radio-secure] exists in extensions.conf, the card adds exten => 1000,1,rpt,1000 to it, unless one already exists. If that context is missing, the card does not invent one. It says so and gives the line to add by hand.

2.5Allmon3

The card adds the node's section to allmon3.ini, and removes it on removal. Allmon3 shows the change after its own restart, which the ASL3 Restart button does with Asterisk.

2.6Apply

  1. The card confirms with the operator before it applies (the page asks "Add private node N to rpt.conf?").
  2. The current files are saved first as an automatic copy, with the label "auto before adding private node N".
  3. Each changed file is written in a safe way: a temporary file is written beside it, then renamed over the old one. The owner, group and mode of the original are kept.
  4. Files whose content would not change are skipped ("unchanged").
  5. Asterisk is not restarted. The result lists the files written, and any automatic copies that were dropped to make room.
Part 3 · Removing a node

Remove only what the card added

3.1What counts as the card's node

The card finds its nodes by the note line above their stanza. A stanza without that note is not its own, even if its number is in the private range. Its exten line is removed from [radio-secure] by matching the node number, and its [nodes] line is removed too.

3.2What removal changes

  • rpt.conf: the note, the stanza and the [nodes] line are removed. Blank lines left in a row are collapsed.
  • extensions.conf: the matching exten line is removed.
  • modules.conf: not changed, because other nodes may use chan_usrp. The card says so.
  • allmon3.ini: the node's section is removed.

Preview and apply work the same way as for adding.

Part 4 · Blocks the card leaves alone

Managed blocks

4.1The marker lines

Some files hold blocks that another tool owns. Such a block starts with a line that says managed by between ; >>> and >>>, and ends with a line of ; <<< ... <<<. The Dashboard's Phone block is one example (the manual describes it this way). The card reads these blocks as a mask: nothing inside them is counted, changed or removed.

4.2What this means

  • A private node that sits inside a managed block is not changed by the card. The card still counts every section header in the file, managed or not, as a used number, so it will not reuse that number.
  • The card lists nodes it left alone, with the reason, in its notes. For example: a private node in the dashboard's Phone block, or node 1921.
  • Node Talker's node 1921 is added from Node Talker's own TX card, not from this card.
Part 5 · Presets and other paths

Other ways the same file changes

5.1The Travel Node preset

The Config tab can save this node's wiring, including its private nodes, as a preset, and apply it on another node. A preset holds no callsigns, IDs or passwords. Applying a preset removes the private nodes it does not list, and the preview shows "PRIVATE NODES THAT WILL BE REMOVED" before anything changes. The preset path was read in part; its full steps are not described here.

5.2Automatic copies and save points

  • Every apply first saves an automatic copy. The copies are kept under the config folder's auto directory.
  • The limit is 10 save points (_CFGR_MAX_POINTS). When the total passes it, the oldest automatic copies are removed. Copies the operator saved by hand are kept, and saving one by hand is refused when 10 already exist.
  • A copy can be restored from the Config tab's restore section (the restore path was not traced in full).

5.3A reinstall is marked pending

After a successful private-node change, or other config change, the helper writes a "reinstall pending" note. It is a reminder that a reinstall of the tools may be wanted (Stage 1.5, Part 5). It does not start one.

5.4No change during a reinstall

The config actions run under a lock, so two changes cannot run at once. The reinstall job (Stage 1.5) is a separate process; the page does not block a private-node change while it runs, so the operator should not make one during a reinstall.

Part 6 · Safety checks

What stops a bad edit

  • Number rules. Only 1000 to 1999, not reserved, not already used.
  • Port rules. USRP ports must be numbers from 1 to 65535, must differ from each other, and must not be used by another USRP node.
  • Missing file. If rpt.conf is missing, the card stops and says to install ASL3 first.
  • Preview. Nothing is written until the operator applies.
  • Atomic write. A file is replaced only after its new copy is written in full.
  • Automatic copy. The files are saved before every change.
  • Root. Every config change first checks that the helper runs as root.

6.1What the card does not check

The card does not test whether Asterisk accepts the new stanza. It does not check the USRP channel itself. A node that is written correctly can still fail to link until Asterisk is restarted and reloaded, and the operator is told to restart it by hand.

Part 7 · Points for the book

What the editor shows

7.1It edits text, not an API

The card edits the same files Asterisk reads. It does not use a database or a shadow copy, so what the operator sees in rpt.conf is what Asterisk gets. The book can say so plainly.

7.2Ownership by a marker line

A node the card added is recognised by one note line. That is simple and easy to check by eye, but a person who edits the stanza or deletes the note will make the card treat it as a node it did not add. The book should tell operators to leave the note in place.

7.3Not checked

  • The preset apply and restore paths, which were read in part.
  • How Asterisk treats the new stanza once it is loaded.
  • The Allmon3 section format beyond the host, port, user and password lines the card copies.
