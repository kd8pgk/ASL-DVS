Part 2 · The platform

The board, the OS and the network

2.1How it is read

The platform reader is the shared function system_profile, copied unchanged from shared/confio.py (see the Common Functions Sheet). It is called once, the first time the helper needs it, and the result is kept for the life of the process.

FieldWhere it comes from
board, model/proc/device-tree/model. A board is "pi" if the model names a Raspberry Pi, otherwise "other".
os_id, os_name, codename, version_id/etc/os-release: ID, PRETTY_NAME, VERSION_CODENAME and VERSION_ID.
archdpkg --print-architecture, or the machine name from uname if dpkg is not there.
wifi_managerNetworkManager if its service is active; else wpa_supplicant if its socket folder has files; else systemd-networkd if active; else "unknown".
wifi_iface, wifi_ifacesThe wireless interfaces under /sys/class/net. The one that is up is preferred; else wlan0; else the first one.

If the reader fails, the helper uses a blank platform with the board set to "other". The helper still runs.

2.2What the platform is used for

  • The default distro for install steps is the OS codename if it is bookworm or trixie; otherwise trixie. The install tabs can still be set to the other release.
  • The platform text in the header reads the OS name, the architecture and the board.
  • Ampersand checks, on the node itself with a shell line, that VERSION_CODENAME is trixie before anything else is done (Stage 1, Part 5.5).

The cache is kept for the life of the process. After an OS upgrade the helper must be restarted before it reports the new codename.

3.2How it is read

  1. One dpkg-query call lists every package with its status.
  2. For each product, its packages are taken from that list. A package counts when its status says it is installed.
  3. Its program files are checked with a file-exists test.
  4. Its units are read with one systemctl show call, giving the load state, the active state and the unit-file state. A unit that is masked is flagged.
  5. Leftover paths and removed packages with kept settings are noted.

The whole result is kept for 20 seconds. A refresh with force=1 bypasses it.

3.3The states

StateMeaning
installedA core package, a core program file, or a core unit is present.
brokenA package is half-installed (its status is not a clean install), or the package is installed but its working parts are missing (for example the package is there but the expected file is not). The note sends the operator to the Update tab's package recovery steps.
leftoversNothing is installed, but a package has its settings kept, or a leftover path, a program file or a unit file remains.
absentNone of the above.

A product found only by its program file is noted as "found by file", not as a package install. A masked unit is listed in the notes.

Part 4 · Tunnel and firewall

What the helper checks about the tunnel

  • wg0 present: the interface's folder exists under /sys/class/net.
  • wg0.conf permissions: the file must be mode 600. If not, the self-check warns that the private key's permissions have drifted.
  • The 44NetConnect zone: its ports and services, read from firewalld (cached). If the zone does not exist yet, the self-check says that is expected before the tunnel's steps 2 to 6.
  • Exposure: the self-check looks for the helper's own port, the other dashboard ports it watches, and the Asterisk AMI port in that zone. Any of them exposed is a danger finding. A clean zone gives an "ok" finding.
  • Configured tunnels: the names of the tunnels in the config (for example the Pi's tunnel and any router tunnel).

The self-check looks at exposure, not at what is installed. Installation is read in Part 3 and Part 5.

Each step of the tunnel setup has one status function that answers "done" or "not done", with a few facts behind the answer. The Overview combines them. The step numbers match Stage 2.

The report is built as text, or as JSON with --json (Stage 1.5). Its findings are warnings about things it can see. The manual lists the kinds, such as a restarted unit, a service that never started, an unsynchronised clock, or under-voltage.

7.2Snapshots

A background loop saves a snapshot of the boot record 6 minutes and 25 minutes after each boot. Each snapshot is kept to 64 KB, and the snapshots are listed under "Saved copies of earlier boots" on the Boot tab.

Part 8 · Points for the book

What the readings show

8.1The readings are read-only

Every reader in this summary only reads. The book can say that looking at the state changes nothing on the node.

8.2Some readings are cached

The platform is cached for the life of the process, the products for 20 seconds, and the resolver answer for a while. A reading can be a little old, and a restart or a forced refresh brings it up to date.

8.3Product detection is by name and by file

A product is found by its package name pattern and its program files. A hand-built program with no package is found only if its file is in the list. The book should say which products are matched by package and which by file.

8.4The self-check checks exposure

It does not check that the tunnel works, nor that the packages are installed. Those are the readiness steps in Part 5.

8.5Not checked

  • The Nodes tab, which reads the ASL node's own state through Asterisk.
  • The router probes, which connect over SSH to the router.
  • The exact dpkg and systemctl output on a live node. The parsing was read against the expected formats.
