What 44helper is

1.2Installing it

44helper is optional. Install it like the other tools: from instmon's page (Components, or GitHub Updates), with the installer, or by itself:

sudo python3 44helper_v0_0_195_20261013.py --install
# and to remove it
sudo python3 /usr/local/bin/44helper.py --uninstall

--install copies the file into /usr/local/lib/asl_dvs/44helper/, links it as /usr/local/bin/44helper.py, writes 44helper.service, which starts through the shared launcher /usr/local/bin/asl_dvs_launch.py, and starts it. Its settings live in /etc/44helper/44helper.conf; an uninstall leaves them in place.

1.3Logging in

  • Open http://<pi-address>:9997 and log in with the Pi's root password. 44helper has its own login, separate from the Dashboard and SysMon.
  • The login doesn't time out, because install jobs can run for a long time. It ends when you press Log out, when anyone presses Log out all devices, or when the Pi reboots.
  • Wrong passwords share one 5-try lockout across the login, the terminal and every other password prompt.
  • If 44helper restarts while you are logged in, the page reconnects to any running job by itself.
CAREFUL44helper can install, remove and reconfigure anything on the Pi. Keep port 9997 on your own network. Never open it in a firewall zone or publish it through Cloudflare. The Overview's self-check turns red if it ever becomes reachable through the 44Net zone.

The page, step cards and the safety checks

Most tabs are a numbered list of step cards. This chapter explains how a card works, what 44helper checks before it runs a step, and what to do when it refuses.

2.2Checks before a step runs

You can Turn on each one, or Put the mask back (on purpose), which 44helper then leaves alone. While a mask can't be cleared, the card is red and the install buttons are locked.

2.3How long a step may run

  • Package and install-script commands (apt, dpkg, | bash, install*.sh, builds) have no time limit. They run as their own systemd job, so they carry on if 44helper restarts, and the page re-attaches to them.
  • Anything else stops after 15 minutes unless the step sets its own limit.
  • Pi tunnel step 6 waits up to 90 seconds for the tunnel to start (Chapter 7).

2.4The built-in terminal

A few steps need you to answer questions on screen: asl-menu, the USRP2M17 installer and Ampersand's first run. Their cards can open a real terminal in the page, but only:

  • after it has been switched on, from the page with the root password, or by creating /etc/44helper/terminal.enable over SSH (owned by root, not writable by others);
  • from your local network, never through a tunnel or Cloudflare;
  • with the root password entered again each time you open it;
  • for the one command printed on that card, nothing else.

One terminal at a time. It closes after 10 minutes with no typing, or when you log out.

Chapter 5 · Full Tunnel tab

The half tunnel card TESTING

A full tunnel makes your 44 address reachable by anyone, but sends all the Pi's traffic through 44Net. A split tunnel keeps the Pi's traffic at home, but only 44Net hosts can reach you. The half tunnel takes the useful half of each: anyone can reach ASL and EchoLink at the 44 address, and everything else keeps the normal route.

5.1What changes

TrafficGoes
Asterisk (AllStar links, registration, EchoLink)through the tunnel, from the 44 address
Anything sent from the 44 addressthrough the tunnel
The IAX port and EchoLink 5198-5199/udp, 5200/tcpthrough the tunnel
Traffic to 44Net, the LAN, and the tunnel server itselfits normal route
DVSwitch, usrp2m17, DNS, updates, everything elsethe normal internet link

How: wg0 runs with Table = off and AllowedIPs = 0.0.0.0/0, so WireGuard accepts packets from any address but adds no routes. A route table (4444) with a default route via wg0 and six routing rules (priority 1100–1105) pick out Asterisk's traffic. The first rule, lookup main suppress_prefixlength 0, keeps the LAN, 44Net and the tunnel server on their normal routes.

CAREFULWith the half tunnel on, other nodes and EchoLink reach you at the 44 address only. A router port forward to the IAX or EchoLink ports stops working, because Asterisk's replies go out the tunnel from the 44 address. Everything open in wg0's firewall zone is reachable from the whole internet.

5.2Before you start

  • The Full Tunnel or Split Tunnel tab done, with the tunnel working. A split config is fine: the test uses a copy set to 0.0.0.0/0.
  • Asterisk running as its own asterisk user (ASL3 does). As root, only the IAX and EchoLink ports use the tunnel, and registration still shows your home address.
  • Do it from home, on the LAN, not over the tunnel.

5.6Make permanent

Unlocks when steps 2–6 are done and the last checks, run after them and under 15 minutes old, are all green or grey. Type the user whose home folder gets the removal script (default: the UID 1000 user; root or a login user, UID 1000 and up, only). Then it:

  1. Saves each piece in its normal home: wg0.conf gets Table = off, AllowedIPs = 0.0.0.0/0 and the routes and rules as PostUp/PostDown lines between # 44helper-half-begin and # 44helper-half-end (they work out the gateway at start-up, so a travel node on another network still works); firewalld gets the ports in wg0's zone; /etc/sysctl.d/90-44helper-halftunnel.conf gets the return-path setting.
  2. Writes remove_half_tunnel.sh and a 0600 copy of the original wg0.conf into that home folder and /root, and a login reminder in /etc/profile.d/.
  3. Clears the test, starts the tunnel from the saved wg0.conf, reloads the firewall and runs the checks again.
  4. If a check fails, it takes everything back out and restarts the test with a fresh 15-minute timer. If a check is only waiting (registration), it stays saved.

5.7Remove permanent

Runs the same steps as ~/remove_half_tunnel.sh. The script is plain bash, needs no 44helper and asks for sudo by itself. It stops the tunnel, removes the marked lines and puts AllowedIPs back (so any other edits to wg0.conf are kept), deletes the rules and routes, closes the ports it opened, removes the sysctl file and starts the tunnel again. If the marked lines can't be taken out, it restores from a backup, root-owned copies first.

Why split only lets 44Net in: a packet from an ordinary internet address does arrive down the tunnel, but WireGuard checks its source against AllowedIPs and drops it. That is why a split tunnel keeps your home address and router forward for ASL.

Half vs full with exceptions: both let anyone reach the 44 address. They differ in what happens to traffic that isn't on a list. With full with exceptions it goes through the tunnel, so the whole Pi shows up as the 44 address, and each service that misbehaves needs an exception.

6.2Which to pick

  • Split: your ISP gives you a public address with a router forward for ASL, and you want 44Net peers too. The lowest-risk mode.
  • Half: ASL should be reachable at the 44 address with no router forward, or you're behind CGNAT, and the rest of the Pi should be left alone. The safest way to do that on a DV node.
  • Full with exceptions: the whole Pi behind the 44 address, but forwarded dashboard and SSH connections should still answer.
  • Full on its own: a Pi that is only reached through 44Net.

Chapter 7 · Remote access

Full Tunnel and Split Tunnel tabs

Both tabs set up WireGuard (wg0) on the Pi and a firewalld zone called 44NetConnect that decides what the 44Net side can reach. The steps are the same; the only difference is the AllowedIPs line in the config you paste.

44Net Connect gives every tunnel the same config, with AllowedIPs = 0.0.0.0/0. The Split tab needs 44.0.0.0/9, 44.128.0.0/10 instead. From 0.0.200 you paste the config as it is: step 4's check offers to rewrite that line. A 44Net Connect tunnel is a single address, not a routed subnet; for a subnet use the Router Install tab.

Update and System Optimization

12.1Quiet mode

Before a big upgrade or install, quiet mode pauses everything that competes for the SD card, in four tiers:

  1. watchdogs and update timers (the Node Controller watchdog, monit, the ASL3 node-list and database timers, man-db);
  2. background disk users (the performance recorder, PackageKit, the manual-page indexer);
  3. the suite's web tools (SysMon, the Dashboard, instmon, the SvxLink and M17 dashboards, and lighttpd, the DVSwitch web page);
  4. the radio services (Asterisk, the bridges, md380-emu, SvxLink, ircDDBGateway, STFU).

Turn off restarts exactly what was paused, in reverse. 44helper, wifimon, SSH, Cockpit, networking and the firewall are never touched. The card shows the commands first. A left-on quiet mode is restored when 44helper starts.

CAREFULThe node is off the air while quiet mode is on, and it stays on until you turn it off: no 30-minute auto-restore, unlike instmon's Quiet System. It can't be turned on while a package job holds apt's locks. If something doesn't come back, the card shows the likely cause and offers Reboot node.

13.3Common tasks

Undo a change that broke the node

  1. Restore: pick the save point or automatic copy from before the change.
  2. Tick the system involved and press Restore selected.
  3. Restart what Restart services lists, or run Finish: reinstall and reboot.

Copy a travel setup to a new Pi

  1. On the working node: Travel Node preset, Preview, Save as Travel Node.
  2. On the new node, with the same instmon library: install the software (Part IV), then Restore → Travel Node.
  3. Identity: set this node's callsign everywhere, and fill in its IDs and passwords until every group matches.

Copies are kept in /etc/asl_dvs/instmon_library/config_restore/ (automatic copies under auto/), so instmon's Backup & Export ZIP includes them. Each restored file is written through a temporary file (mode 600, no symlink following), then given the saved owner and mode and swapped into place.

14.1A step says NOT RUN

  1. Read the reason in its output: masked services, or broken packages.
  2. Masks: use the card at the top of the tab. Broken packages: follow What to do next to the Update tab's recovery steps.
  3. Come back with the link at the top of the Update tab and run the step again.

14.2The tunnel won't start

sudo wg show wg0
The log stops atCause and fix
resolvconf -a wg0, 25 s, "org.freedesktop.resolve1: timed out"systemd-resolved isn't answering on D-Bus. sudo systemctl restart systemd-resolved; if timeout 5 resolvectl status still hangs, reboot. Or remove the DNS = line.

Up but no handshake, or the dashboard says idle: first run ip -4 route get <endpoint>. If it says dev wg0, the tunnel server is routed into its own tunnel: Split tab step 4b, Fix the tunnel-server route (section 7.3). Otherwise check the key and the Endpoint on connect.44net.cloud, and that UDP out to the Endpoint isn't blocked. Your Address should be what the portal shows (a single 44Net Connect address is a /32).

14.3I lost access after a tunnel change

  • A half-tunnel or exceptions test takes itself out after 15 minutes, or at a reboot.
  • A permanent one: log in at a keyboard and screen, or over SSH from the LAN, and run ~/remove_half_tunnel.sh or ~/remove_full_exceptions.sh.
  • A plain full tunnel and router-forwarded SSH: use the LAN, or the full tunnel with exceptions (Chapter 8).

14.4DVSwitch or M17 stopped after the tunnel came up

  1. Split tab: a pasted full config sends DNS into the tunnel. Step 4b, Repair AllowedIPs.
  2. Bridges won't start at boot: the Health and fixes card's Apply netcheck fixes, or the netcheck card under step 6 (Chapter 7). From 0.0.200 step 6 and the DVSwitch installer do this by themselves.
  3. Full tunnel: outbound block rules (Full tab 4b) or a master that refuses the 44 address. Try the half tunnel, or put the master on the exceptions bypass list.

14.5The Pi runs out of memory

Check swap is on: swapon --show. If an older 44helper turned it off, use Swap — restore (Chapter 12) or sudo systemctl enable --now dphys-swapfile.
