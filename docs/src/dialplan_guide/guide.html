1 · Overview

The big picture

A phone call on an AllStar node is handled by three parts of the same Asterisk program. Each has its own config file and its own job:

PartConfigJob
The dialplanextensions.confDecides what happens to every call: which number goes where, what is checked first, when to answer, ring or hang up.
app_rpt (AllStar)rpt.confRuns the nodes: radio audio, links between nodes, DTMF codes, keying the transmitter. Its rpt() app joins a call to a node; its autopatch places calls from the radio.
The channel driverspjsip.conf, iax.confTalk to the outside world: SIP providers (VoIP.ms, Hams Over IP, AmateurWire) and IAX2 servers, including signing in.

A call always enters the dialplan somewhere (a context), follows its steps, and usually ends in one of two places: Dial() (ring the outside world) or rpt() (join an AllStar node). The radio is never connected to a phone directly; it is always the node in the middle.

  1. RadioYour handheld or mobile, on the node's radio interface (SimpleUSB on node 652702 in the examples).
  2. Radio nodeapp_rpt node 652702. Keys the transmitter when a linked node or call has audio for it.
  3. Phone nodeA private node (1001) with no radio of its own. Linked to the radio node while the Phone tab is open.
  4. The callJoined to the phone node with rpt(1001,Pv), or (stock) carried by the node's autopatch.
  5. Phone networkPJSIP or IAX2 channel to the provider, created by Dial().
WHYNode Controller keeps the phone on its own node so the radio node's settings (simplex, hang time, links to the DMR and M17 bridges) are never mixed with phone settings, and so each phone network can have its own codes and rules.
2 · Files

Where the files live

Everything is in /etc/asterisk. Asterisk reads each file when its module loads, and again when you reload that module.

FileRead byReload withOwned by
extensions.confpbx_configdialplan reloadYou (stock file). Node Controller adds one include line at the end.
dvs_phone_extensions.confpbx_config (included)dialplan reloadThe Dashboard. Rewritten on every Save Phone.
rpt.confapp_rptmodule reload app_rptYou. Node Controller writes only between its two marker lines, plus one line per phone node in [nodes].
pjsip.conf + dvs_phone_pjsip.confres_pjsipmodule reload res_pjsip.so (and res_pjsip_outbound_registration.so)You / the Dashboard (included file).
iax.conf + dvs_phone_iax*.confchan_iax2iax2 reloadYou / the Dashboard (included files).
modules.confAsterisk at startrestart AsteriskYou. Node Controller adds load => lines for the phone modules.

Includes

A config file can pull in another file. Node Controller uses the safe form, which is silently skipped if the file is missing:

extensions.conf
; last line of /etc/asterisk/extensions.conf
#tryinclude dvs_phone_extensions.conf

An included file behaves exactly as if its text were pasted at that spot. Its contexts become part of the one big dialplan, so a stock context and a Node Controller context can jump to each other with Goto. The SIP file is included at the end of pjsip.conf the same way; the IAX2 sign-in file goes right after [general] in iax.conf, where register => lines must be.

The rpt.conf markers

The phone nodes are written into rpt.conf itself, because app_rpt needs every node in that one file. The Dashboard only ever touches the text between these two lines:

rpt.conf
; >>> dvs-phone (managed by asl_dvs_dashboard - edits inside are overwritten) >>>
[1001](node-main)
 ...
; <<< dvs-phone <<<

It also adds each phone node to the [nodes] list (1001 = radio@127.0.0.1/1001,NONE) so the radio node can link to it over the Pi's own IAX2 port.

CAREFULEdits you make inside the markers, or inside dvs_phone_*.conf, are lost on the next Save Phone. Put your own contexts and nodes outside them. The Dashboard refuses to save if rpt.conf already has a [<node>] or [functions<node>] section it didn't write. It doesn't check dialplan contexts, so don't give your own contexts names starting with dvs-.

The first time the Dashboard changes one of your own files (rpt.conf, extensions.conf, pjsip.conf, iax.conf, modules.conf), it keeps a copy next to it named <file>.dvsphone.bak.

When changes take effect

  • The Dashboard reloads what it changed after Save Phone: the dialplan, app_rpt, PJSIP or IAX2.
  • New SIP modules need one Asterisk restart (tick Restart Asterisk if needed on the Edit page).
  • About 20 seconds after the Dashboard starts, it compares what it would write with what is on disk and refreshes anything stale. That is how upgrades to the dialplan reach your Pi.
3 · Syntax

Anatomy of a dialplan line

The dialplan is a list of contexts. Each context is a list of extensions. Each extension is a numbered list of steps (Asterisk calls them priorities). Each step runs one application.

The parts
[dvs-node-dvshoip]                          ; the context name, in square brackets
exten => _X.,1,Set(DVSNET=dvshoip)          ; extension _X., step 1, app Set
 same => n,Set(DVSOPT=)                     ; same extension, next step
 same => n(net),GotoIf(...)                 ; next step, with the label "net"
 same => n,Goto(dvs-net-dvshoip,${EXTEN},1) ; jump to another context
exten => i,1,Goto(dvs-invalid,s,1)          ; a second extension: "i" (invalid)
PieceMeaning
[name]Starts a context. Everything below belongs to it until the next [...].
exten =>Starts an extension: exten => what-was-dialed, step, App(arguments).
_X.The extension. A leading _ makes it a pattern (section 4); without it, it is matched literally, e.g. 911 or s.
1The first step. Every extension must have a step 1.
same =>Continue the extension above, so you don't repeat the pattern.
n"Next": the step after the previous one. Asterisk numbers them 2, 3, 4… for you.
n(net)Next step, and give it the label net so Goto / GotoIf can jump to it by name.
App(args)The application and its arguments, separated by commas.
; textA comment. Ignored by Asterisk.

How a call walks through it

  1. The call arrives in a context with a number (the extension).
  2. Asterisk finds the best matching exten => line and runs its step 1.
  3. It then runs step 2, 3… in order, unless a step jumps somewhere else (Goto, GotoIf).
  4. An application such as Dial or rpt holds the call while it runs; when it returns, the next step runs.
  5. Running off the end, or Hangup(), ends the call.

Jumps

FormGoes to
Goto(label)A label in the same extension.
Goto(exten,step)Another extension in the same context.
Goto(context,exten,step)Another context. Node Controller uses this to pass a call along: Goto(dvs-net-dvshoip,${EXTEN},1) keeps the dialed number.
GotoIf($[test]?yes:no)Jump to yes if the test is true, no if false. Either side may be left out: GotoIf($[test]?open) simply carries on when false.
TIPRead a context from the top of the matching extension downwards, and follow each Goto. That is exactly what SysMon's Dialing rules card does for you.
4 · Syntax

Patterns

An extension that starts with _ is a pattern: it matches many numbers. Each character stands for one digit position, except . and !.

CharacterMatches
XAny digit 0–9.
ZAny digit 1–9.
NAny digit 2–9 (the first digit of a North American area code or exchange).
[15-7]One digit from the set: here 1, 5, 6 or 7.
.One or more of anything (digits, *, #).
!Zero or more of anything, and match as soon as possible.
Any other characterItself, e.g. _1800NXXXXXX needs a literal 1800.

Patterns used in these dialplans

PatternMatchesUsed for
_NXXNXXXXXX10 digits, valid area code and exchangeUS/Canada number without the 1
_1NXXNXXXXXX1 + 10 digitsthe same number with the 1
_NXXXXXX7 digitsstock: local number (adds your area code)
_X11211, 311 … 911stock: service codes
_1800NXXXXXXtoll-free 800 numbersblocked list
_1NXX555XXXXany 555 exchangeblocked list (directory and fictional numbers)
_011.011 and moreinternational (only if allowed)
_X.a digit then anything"everything else": catch-alls and extension dialing
_[+0-9].a digit or + then anythingincoming caller ID or DID numbers
_XXXX!4 or more digitsstock: node numbers in radio-secure
NOTEThe exchange (the 3 digits after the area code) must start with 2–9 too. A number like 555-123-4567 matches neither _NXXNXXXXXX nor _1NXXNXXXXXX, and the Dashboard refuses it before dialing. That is why the examples here use 555-234-5678.

Which line wins

When several patterns match, Asterisk picks the most specific one: an exact number beats a pattern, and a pattern with fewer possibilities beats a looser one. So in the VoIP.ms rules below, 911 wins over _X. even though both match. In the next context, dvs-net-dvsvoipms-r (section 11), the blocked _1800NXXXXXX wins over the general _1NXXNXXXXXX the same way.

dvs_phone_extensions.conf
[dvs-net-dvsvoipms]
exten => 911,1,NoOp(911 - E911 is set up on this network)
 same => n,Set(CALLERID(num)=5550001111)
 same => n,Dial(PJSIP/911@dvsvoipms,60)
 same => n,Hangup()
exten => _NXXNXXXXXX,1,Goto(dvs-net-dvsvoipms-r,1${EXTEN},1)
exten => _1NXXNXXXXXX,1,Goto(dvs-net-dvsvoipms-r,${EXTEN},1)
exten => _X.,1,Goto(dvs-invalid,s,1)
exten => i,1,Goto(dvs-invalid,s,1)

Special extensions

ExtensionWhen it runs
s"Start": a call that arrives with no number (many incoming SIP calls).
i"Invalid": a number that matches no line in this context.
t"Timeout": the caller didn't enter anything in time.
h"Hang-up": runs after the call ends (not used here).
CAREFULA single digit never matches _X.: the dot needs at least one more character. That is why the autopatch waits for at least two digits.
5 · Syntax

Variables, functions and tests

Anything inside ${ } is replaced by its value before the step runs.

WrittenValue
${EXTEN}The number being handled, e.g. 15552345678.
${EXTEN:1}The same, minus its first character: 5552345678. (:2 drops two, and so on.)
${CALLERID(num)}The caller's number.
${CALLERID(num):-10}Its last 10 characters, so +15553456789 and 15553456789 both become 5553456789.
${DB(dvsphone/active)}Reads a value from Asterisk's database (AstDB): family dvsphone, key active.
${DB_EXISTS(dvsphone/then)}1 if the key exists, 0 if not.
${DB_DELETE(dvsphone/then)}Returns the value and deletes the key, so it is used exactly once.
${DVSNET}, ${DVSOPT}Variables set earlier in the same call with Set().

Setting variables

Examples
 same => n,Set(DVSNET=dvshoip)                              ; a channel variable
 same => n,Set(CALLERID(num)=5550001111)                    ; a function can be written to
 same => n(then),Set(DVSOPT=D(${DB_DELETE(dvsphone/then)})) ; read-and-delete

Tests

$[ ... ] works out an expression: =, !=, <, >, & (and), | (or), + - * /. When both sides are numbers they are compared as numbers, otherwise as text. A value that might be empty would leave a gap in the expression, so Node Controller puts quotes around such values:

Tests used here
; incoming: only if the Phone tab is open AND this network is the picked one
 same => n,GotoIf($["${DB(dvsphone/open)}" = "1" & "${DB(dvsphone/active)}" = "dvshoip"]?open)

; outgoing: stop if the phone patch is switched off
 same => n(net),GotoIf($["${DB(dvsphone/patch)}" = "0"]?bad)

; PIN: count the tries
 same => n,Set(TRIES=$[${TRIES} + 1])
 same => n,GotoIf($[${TRIES} >= 3]?bye)
WHYReading switches from AstDB lets the dialplan react the moment you change something on the Phone tab, with no reload: the Dashboard writes dvsphone/open when you open the tab, dvsphone/active when you pick a network, and dvsphone/patch when you turn the patch on or off.

7 · Calls

Channels and calls

Every leg of a call is a channel. A channel has a technology, a name, and a place in the dialplan. Two channels talking to each other are in a bridge.

Channel name looks likeWhat it is
PJSIP/dvsvoipms-0000002aA SIP call leg to or from the VoIP.ms account.
IAX2/dvsclub-1234An IAX2 call leg to or from an IAX2 phone network.
Local/5552345678@dvs-node-dvsvoipms-00000003;1Half of a Local channel: a call Asterisk places to itself, into a context.
...;2The other half of the same Local channel. It runs the context's steps (here, Dial).

Local channels

Local/number@context lets a program start a call into any context as if someone had dialed number. It always comes as a pair:

  1. Half ;1Runs whatever the caller asked for: here the app rpt(1002,Pv), once the call is answered.
  2. Half ;2Walks the context: dvs-node-dvsvoipms → dvs-net-dvsvoipms → -r → Dial().
  3. PJSIP legCreated by Dial(). When the far end answers, ;2 answers, which answers ;1.

The /n at the end (Local/...@dvs-node-dvsvoipms/n) tells Asterisk not to optimise the pair away after answer, so the call keeps a stable shape the Dashboard can follow.

Originate: placing a call from a program

The Dashboard talks to Asterisk over the Asterisk Manager Interface (AMI). To place a call it sends:

AMI Originate (sent by the Dashboard)
Action: Originate
Channel: Local/5552345678@dvs-node-dvsvoipms/n  ; dial this, through this context
Application: Rpt                                ; once answered, run this app ...
Data: 1002,Pv                                   ; ... with these arguments
Timeout: 65000                                  ; give up after 65 s of ringing
Async: true                                     ; don't wait; report back later

So a Dashboard call is really two things glued together: the ordinary dialing rules (on ;2) and rpt(1002,Pv) (on ;1). If the far end is busy or never answers, ;1 is never answered and rpt() never runs: nothing touches the radio.

TIPIn core show channels during a Dashboard call you will see three lines: the PJSIP (or IAX2) leg running AppDial, Local/...;2 running Dial, and Local/...;1 running Rpt.

9 · AllStar

Inside autopatch

Autopatch is app_rpt's built-in phone patch. Knowing its states explains both how stock dialing works and why Node Controller stopped using it for the call itself.

StateWhat is happening
DOWNNo patch.
DIALING*61 was keyed; digits are being collected (dial tone unless quiet=1).
CONNECTINGThe number is complete; the dialplan is running (Dial() is ringing).
UPThe call is connected.
FAILEDThe number can't match anything in the context; congestion until the patch is taken down.

How it knows the number is complete

  1. Each digit is added to the number and checked against the context's patterns.
  2. If the number matches a line and no longer number could match, it dials at once.
  3. If a longer number could still match (always the case with _X.), it waits 1.5 seconds after the last digit, then dials.
  4. If no digit arrives for dialtime (20 s here), it gives up.

How it ends

With farenddisconnect=1, or on any half-duplex node, the patch goes down as soon as the dialplan finishes or the far end hangs up. Otherwise it waits for the autopatchdn code.

The dead key

While a patch is in DIALING, CONNECTING or UP, app_rpt keys every linked node for the whole call, whether or not anyone is talking. The code that would gate this by voice exists, but is compiled out because it clipped the first syllable on links:

app_rpt.c, per-link keying (master d392975, lines 4916–4921)
mycalltx = myrpt->callmode;
#ifdef DONT_USE__CAUSES_CLIPPING_OF_FIRST_SYLLABLE_ON_LINK
    if (myrpt->patchvoxalways)
        mycalltx = mycalltx && ((!myrpt->voxtostate) && myrpt->wasvox);
#endif
totx = ((l->isremote) ? (remnomute) : (myrpt->localtx && myrpt->totimer) || mycalltx) || remrx;
  1. Phone node 1001 is in autopatchcallmode is not DOWN, so it keys its link for the whole call.
  2. Radio node 652702 sees the link keyedIt transmits the link audio, continuously.
  3. Your simplex radio can't receiveThe hotspot is transmitting, so it never hears you key up.
  4. ResultReceive audio works, but nothing you say reaches the call. *99 seems dead.
WHYA full-duplex repeater doesn't mind; a simplex hotspot can't work with it. Settings such as duplex, vox* or voxalways never reach the line above, so no rpt.conf setting can fix it.

What Node Controller does instead

Since 9.3.71.8-pi02w and 9.3.73 the call never lives in autopatch. Calls dialed from the Dashboard and incoming calls join the phone node with rpt(<node>,Pv), phone mode with VOX: the same mode as the stock _3. example in [allstar-sys] (the stock [iax-client] uses plain P). *61 from the radio still uses autopatch, but only to collect the digits: its context hands the number to the Dashboard and hangs up, so the patch drops at once and the Dashboard places the call the same Pv way. The link is keyed only for those few seconds of dialing.

How Pv keys

  1. The far end talksEach 20 ms frame of the caller's audio goes through app_rpt's VOX detector. It turns on after 3 voiced frames and off after 20 quiet ones (about 0.4 s), so pauses between words don't drop it.
  2. The call counts as receivingWhile VOX hears voice (or *99 has it keyed), the phone node treats the call's link as receiving, and keys its other links: the one to your radio node.
  3. The first word survivesWhen VOX first triggers, simplexphonedelay (25 × 20 ms, about 0.5 s) of silence goes in front of the audio, so the transmitter is up before the words arrive.
  4. The far end stopsVOX drops, the link unkeys, your hotspot goes back to receive, and what you say goes into the call.
  5. Nobody holds it foreverAfter voxtimeout (10 s) of nonstop far-end audio, VOX is forced off for voxrecover (2 s) so the radio side can break in.

Source, app_rpt master d392975: option parsing app_rpt.c 7354–7367; link VOX and timeout 3567–3581; keying other links 4898–4906; first-word delay 5014–5030; VOX detector rpt_vox.c dovox(); defaults app_rpt.h 198–205.

Turning stock autopatch on

  1. Uncomment 61 and 62 in your node's function table.
  2. In [pstn-out], replace the "no service" lines with a Dial() to your provider (stock suggests IAX2/allstar-autopatch).
  3. Set HOMENPA in [globals] to your area code, then reload app_rpt and the dialplan.
CAREFULDone on the radio node itself, a stock autopatch call keys that node and every node linked to it for the whole call (section 9): your DMR and M17 bridges would hear the phone too.

14 · Flows

Call flows

A. You press Dial, a favorite, Test call or Voicemail

  1. The Dashboard checksPhone tab open, patch on, a network picked and linked, number rules (911/E911, blocked kinds, international).
  2. It sends OriginateLocal/<number>@dvs-node-<net>/n, Application Rpt, Data <node>,Pv, Timeout 65 s.
  3. dvs-node → dvs-net (→ -r)Patch switch, saved tones, rules, then Dial() on the network.
  4. The far end answersThe Local pair answers; rpt(<node>,Pv) joins the call to the phone node.
  5. VOX keys the linkThe radio transmits only while the far end talks; in the gaps your radio is heard.

B. You key *61 and a number on the radio

  1. DTMF crosses the linkYour radio node passes *61 and the digits to the phone node (link_functions).
  2. Autopatch collects the digitsUnique match, or 1.5 s after the last digit; context dvs-radio-<net>.
  3. System() leaves a notedvs_phone_dialreq writes dial_<number>_<net>; Hangup() ends the autopatch silently.
  4. The Dashboard dialsWithin about 2 s, exactly as route A. The result shows as a Phone tab notice.

C. Someone calls you

  1. The provider sends the callThe account's endpoint (context=dvs-in-<net>) puts it in the dialplan.
  2. Tab open and network picked?No: busy. Yes: trusted number, PIN or straight through.
  3. rpt(<node>,Pv)Joined with VOX; the Phone tab shows the caller and lights a matching favorite.

D. Keypad tones during a call

Send keypad tonesHow the tones travel
Straight to the providerThe Dashboard plays them on the SIP/IAX2 leg (AMI PlayDTMF); SIP sends them as RFC 2833 packets.
Through the callPlayed on the node side so they pass through the call like the radio's own tones; saved favorite tones go in Dial's D() option.
As soundTouch-tone recordings played into the call by dvs-tones and ChanSpy.

E. Hanging up

You useWhat happens
Hang up (Phone tab)The Dashboard hangs up every PJSIP/IAX2 dvs channel and sends rpt cmd <node> autopatchdn to cancel a radio dial still collecting digits.
*62 or *65 (radio)The hang-up script ends every phone call.
The far end hangs upThe call legs close; rpt() returns and the call is gone.

What the Dashboard does around the dialplan

  • Save Phone: writes the files, reloads what changed, checks each phone node is running.
  • Phone tab open: links the picked network's node to the radio node (two-way, or monitor in Listen only), sets open and turns the transmitter time-out off with a safety cap.
  • Every 2 seconds: reads the link list (RPT_ALINKS), fixes a link in the wrong mode, checks the request folder for *61 dials and *980–*982 tones.
  • Dial: Originate (section 7). Hang up: section 14E.
  • Start-up: compares what it would write with the files and refreshes anything stale.

Listen only

With Listen only ticked, the phone node is linked as a monitor link (ilink 2 instead of ilink 3). app_rpt never keys or sends audio over a monitor link, so nothing from your radio, including DTMF codes, reaches the phone node. Check it with:

Link mode
sudo asterisk -rx "rpt xnode 652702" | grep ALINKS
RPT_ALINKS=1,1001RU   ; R = listen only (monitor), T = two-way; K/U = keyed/unkeyed

WHYBoth use the same building blocks: contexts, patterns, Dial() and rpt(). Node Controller writes more of them, keeps them in its own file, and moves the call from autopatch to phone mode so a simplex radio can talk back.
CAREFULTrade-offs of phone mode: no ringback on the air; about half a second of audio delay; after 10 s of nonstop far-end talk the radio unkeys for 2 s (voxtimeout / voxrecover); and radio-dialed calls need the Phone tab open, which is also the only time your radio is linked to the phone node.
