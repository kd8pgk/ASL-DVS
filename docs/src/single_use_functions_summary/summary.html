Part 1 · Method

What "used once" means here

Each Python def and each page-script function was found with a parser or a pattern. Its name was then counted as a whole word in the same file, strings included.

  • Single-use: the name appears twice: the definition and one other place (a call, a table entry, or a button handler).
  • Unreferenced: the name appears only at its definition.
  • Python dunder methods and server hooks (do_GET, log_message, handle_error and similar) are left out, because the framework calls them.
  • The count is per file, and a method name shared by several classes is counted together, so it can hide a single-use method. A helper used once from a loop or a handler may run many times. "Once" is about where it is named, not how often it runs.
  • The pi02w tools and the common tools come first. The full build is listed last, for reference only.

3.1Looks unused, is not

  • Tab functions in 44helper (asl3OnDistroChange, asl3TogglePurge, asl3CustomRun and the dv, svx versions): the page builds the handler name from a prefix at run time ({prefix}OnDistroChange()).
  • Registered by decorator: in SysMon, _phone_sec_health, _phone_sec_calls, _phone_sec_hoip and _phone_sec_modules (pi02w and full build) are added to a section table by @_phone_section. In the full-build SysMon, 22 _cs_* functions (@_con_sum) and 45 _ts_* functions (@_ts) are registered the same way. They are used, by registration.
  • Run on the spot: _wireEdList and _authBoot (Dashboard and SysMon pages) are wrapped in a function that runs at once. Pibrary's $ is a helper whose name is not a word to the counter.
  • Framework hook: visit_Constant in ci/check_repo.py is called by the Python ast visitor.

3.2Why the two unused ones matter

Both sit in 44helper's page script. Removing them is a code change, and under the repo rules it needs a new version of 44helper. This summary changes no code.

Part 4 · Reading the result

Points for the book

  • Half the code is single-use helpers. That is by design. A reader tracing a feature will find that most steps are a function called from one place.
  • The pi02w and full builds repeat each other. The Dashboard and SysMon have near-identical function sets in both builds, so their counts overlap and should not be added together.
  • A word count is a first filter. Registration by decorator, handler names built from a prefix, and immediately-run functions all look unused to it. Check each hit before deleting anything.
  • Not checked: single-use methods whose names are shared with another class in the same file, and functions used only from another file (the shared module is copied into each tool, so its names appear in several files by design).
