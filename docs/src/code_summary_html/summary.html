Part 1 · Scope and method

What was counted

Eight tools serve a web page in the Pi Zero 2 W build. Each keeps its page as markup inside its Python file. The full build and AMP Node Talker are not covered.

1.2How the counts were made

  • The markup was located by its <!doctype> or <html> line and its closing </html>. Counts come from parsing that text.
  • Some pages are assembled at run time from templates and placeholders. For those, the summary describes the source, and the static counts understate the final page. This is noted where it applies.
  • Counts are of the markup in the file. Nothing was loaded in a browser for this stage.

Part 3 · Page by page

Node Controller and SysMon

3.1Node Controller (Dashboard, port 8989)

The page sits in one Python string, from line 7980 to 13839. It has a login screen, a header, a status strip, a tab strip and one panel per mode.

  • Login screen: login-screen, login-card, a password field and a Log In button. Errors appear in login-err.
  • Header: callsign, node number, uptime, a talkgroup indicator, and links to the listen page and SysMon. A perm-link-bar shows a permanent link that is up.
  • Banners: a recording banner (rec-banner) and an offline bar (offline-bar).
  • Tab strip: ASL, ECHO, DMR, STFU, YSF, FCS, P25, NXDN, D-STAR, XLX, M17, Phone and Edit.
  • Panels: one pg-* panel per tab. Each holds a card (for example asl-card), a filter, a reference select, a connect button, a save button, a message line and a grid of entries.
  • Dialogs: three dialog elements for confirmations.

3.2SysMon (port 9999)

The page is one large string from line 1504 to 11141. It is a status monitor with a zone layout, not a set of tabs.

  • Login and offline: the same login pattern as the Dashboard, plus an offline-bar and a restart-banner.
  • Quick links: a bar (ql-bar) linking to Allmon3, DVSwitch, Cockpit, M17, wifimon and the Dashboard.
  • Status strip: host, load, memory, temperature, voltage and registration. Each has its own id (for example s-volt).
  • Command bar: a row of buttons (tbtn-*) for each view: Overview, Services, Ports, Journal, ASL-DVS, Reg, Phone, Tune, Hardware, DVSM, STFU, M17, SD Card and Edit.
  • Content area: zone-content holds one panel per view (for example panel-overview, panel-services, panel-ports).
  • Dialog: one dialog for confirmations.

The ASL-DVS tab keeps its name in the markup (see the naming rules in CLAUDE.md).

Part 4 · Pages

instmon and wifimon

4.1instmon (port 8990)

instmon has two pages in its file.

  • Main page (lines 11602 to 12146), titled for the installer and manager. Its sections are: full update (fu-banners, fu-btn, fu-stop-btn, fu-plan), GitHub update summary and release notes, a channel choice and a build choice, Quiet System and Restore buttons, and a component list with one card per tool (for example confputter-card).
  • Further cards hold a USB import (usbimp-*), a documents list (docs-*), a backup button and a disk-image section (diskimg-*) with a drive table, format options, a console and a backup destination.
  • Suite Log page (lines 6363 to 6609), titled "Suite Log (testing)". It holds a filter form (range, level, kind, search, row limit, order, live refresh), a count line, copy and download buttons for text and JSON, and a coverage table.

Part 5 · Pages

44helper and Node Talker

5.144helper (port 9997)

The page is built by a function that returns the full document (around line 27036). It has five parts:

  • Login screen: a welcome line and a root-password form.
  • Header: the app name, an uptime value, and buttons for Terminal, Log out all devices, and Log Out.
  • Quiet-mode banner (qm-banner), empty unless quiet mode is on.
  • Tab bar built by _render_tab_bar from the tab list (Part 3.6).
  • Panels, one per tab, and a version line at the foot.

The shell is short in the source, so a count of its markup says little about the page. The panels contain most of the controls (see Part 3.6).

5.2Node Talker (port 8993)

The page runs from line 11873 to 12514. Its navigation is three buttons: Connect, Listen and Setup. The icons are placeholders (__ICON_CONNECT__ and so on) replaced when the page is served.

  • Login: a password field and a TLS note (login-tls), since the page can run over HTTPS.
  • Connect tab: a favorites list, a mode and number entry, connect and disconnect buttons, a network choice dialog, and a tune area with its own find and pick controls. Twelve tables hold the lists.
  • Listen tab: a listen button, a volume range control, a status feed, a transmit status, a listener count, a spectrum box, and a gap countdown.
  • Setup tab: the audio, push-to-talk and limits settings, with range sliders and checkboxes.
Part 6 · Pages

Node Recorder and Pibrary

6.1Node Recorder (port 8995)

The page runs from line 7097 to 7449. Its navigation is Schedule, Record and Setup.

  • Schedule tab: a schedule form (title, name, special day, date, weekdays, start and end time, time zone, mode, network and module choice, format, and an enabled flag), a set and clear pair, a rows list, and a results table with a trace.
  • Record tab: a tune area as in Node Talker, and a recordings list. The page has seven tables in all.
  • Login: the same pattern as Node Talker, with a TLS note.

6.2Pibrary (port 9000)

The page runs from line 8544 to 8909. It is a media player, and it is the only page that follows the operating system's light or dark setting.

  • Header: logo, a view button, and a logout button.
  • Tabs: Movies, Audio and PDF. Each tab reads one folder of the library.
  • Mini player: previous, play, next, art, title, restart, shuffle, repeat, rate, sleep, queue, cast and close controls, with an audio element.
  • Queue panel and a picker (filter and list), a popup overlay, and a keyhelp sheet.
  • View panel: theme, size, density and layout options, plus a close button.
  • Global search (gs-input, gs-results), a keep bar, an alert area, and toasts.
Part 7 · Shared structure

What the pages have in common

7.1Login pattern

Every page starts with a login screen that uses the same ids (login-screen, login-card, login-pw, login-btn, login-err). Each one checks the root password through PAM. Sessions and lockouts are covered in the Watchdogs, Guardrails, Locks and Controls summary.

7.2Self-contained pages

  • No page loads an external script or stylesheet. Pibrary links its own web app manifest and icons from its own server.
  • Each page embeds its fonts with two @font-face rules (Readex Pro, weights 400 and 700) as data URIs. The page works offline.
  • Each page sets a viewport meta tag and a language attribute.

7.3Theme

Every page carries a data-theme attribute, and a theme block is inserted before the page's own styles (the __THEME__ placeholder, or _THEME_HEAD in 44helper). Only Pibrary also reads the operating system's dark or light setting, through prefers-color-scheme.

7.4Banners and status

Most pages show a banner above the content when something needs attention: a report, a background job, a quiet-mode state, an offline link, or a pending change. Each banner has its own id.

Part 8 · Points for the book

Things the markup shows

8.1Pages are large single strings

The Node Controller page is about 5,900 lines and SysMon about 9,600, each inside one Python string. Editing them means working inside a string literal. The book should say so, because it shapes how changes are made.

8.2Some pages are built at run time

44helper's tabs, and parts of instmon and Node Talker, are assembled from lists and placeholders. Anyone reading the raw file will miss part of what the user sees. The book should describe these pages from their templates.

8.3Uneven ARIA coverage

The ARIA counts in Part 2.1 vary by a large factor. Before the book claims accessibility for any page, check it with a screen reader or an accessibility audit.

8.4Two login rules in the markup

All eight pages use the same login ids, but the lockout and session rules differ between tools. The rules are in the Watchdogs, Guardrails, Locks and Controls summary. Do not read the shared markup as a shared rule.
