Part 1 · What it is

A phone or laptop page that talks to the node

Node Talker serves a web page. The page listens to the node's receive audio and sends the operator's voice back onto the node's transmit path. It is a common tool: the same file serves both builds, and it is installed by its own --install.

Part 2 · The two paths

Audio goes both ways

2.1Receive (node to phone)

  1. Asterisk sends the node's receive audio to a feed command (outstreamcmd) written into rpt.conf for the chosen node.
  2. The feed command reads that audio and sends it as UDP datagrams to 127.0.0.1:6200.
  3. Node Talker turns the datagrams into 20 ms frames, cleans them, and queues them for each listener.
  4. Each listener reads a stream over HTTP, as u-law by default, or as 16-bit PCM when asked.

Part 2 of this series covers each step.

2.2Transmit (phone to node)

  1. The page opens a WebSocket and sends the operator's microphone audio as 16-bit PCM.
  2. When the operator keys up, the server checks the node is ready and linked, and that the channel is not busy.
  3. Audio is paced out at 20 ms a frame as USRP packets to Asterisk on the transmit node.
  4. Asterisk keys the node's transmitter while the packets flow, and drops the key when they stop.

Part 3 of this series covers each step.

2.3The balancer and the audio settings

The balancer is a set of tone and live checks that the page runs, and it changes settings one at a time. The settings control gain, filtering, the listen buffer and the transmit buffer. Part 4 covers both.

Part 4 · Who may connect

Access, briefly

  • Local network by default. A request from outside the local network is treated as coming from the internet and is refused on the gated routes, unless allow_wan is on. The default is off.
  • Login. The page uses a login with session cookies and lockouts. The security series covers these.
  • Proxied requests are treated as outside, even when their address looks local.
Part 5 · Points for the book

What the overview shows

5.1Two streams, one node

Receive and transmit use different ports and different pieces of Asterisk. A problem on one side does not necessarily affect the other, and the logs and health readings keep them apart.

5.2Node 1921 is a separate node

The transmit path is a second node in rpt.conf, linked to the main node. The receive path uses the main node's own output hook. Operators must restart Asterisk after the rpt.conf change that the setup makes.
