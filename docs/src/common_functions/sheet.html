Part 1 · How the sheet works

What is in shared/confio.py

Code that more than one tool needs is written once, in shared/confio.py, and then copied unchanged into each tool that uses it. The file's USED_BY table lists every function and the tools that carry a copy.

1.1The copy rule

  • Change the reference in shared/confio.py first.
  • Copy the changed function into every tool listed for it in USED_BY. A tool's own wrapper may call the copy.
  • ci/check_repo.py fails any tool whose copy differs from the reference.
  • Tool files carry no comments or docstrings (a repo rule), so each copy should match its reference exactly.

1.2Parity check for this sheet

Each of the 13 functions was compared with every copy listed in USED_BY: 52 copies in 11 tool files. Each comparison matched the reference structurally (syntax tree, ignoring comments). No copy differed and no listed copy was missing.

The repository clone used for this sheet has no origin/main branch, so ci/check_repo.py itself was not run. Run it before any pull request that touches shared/confio.py.

Part 3 · Files and config

Writing and filling files

3.1atomic_write(path, data, mode=None, new_mode=0o600, skip_same=False)

Returns True when the file was written, False when it was skipped.

  • Writes to a temporary file in the same folder, created with mode 0600, then syncs it to disk and replaces the target in one step. A reader sees the old file or the new one, never a part of each.
  • When run as root and the file already exists, keeps the file's owner and group.
  • Mode: the explicit mode if given, else the existing file's mode, else new_mode (0600 by default).
  • skip_same=True returns False and writes nothing when the content is already identical.
  • On any error the temporary file is removed and the error is raised again.

3.2fill_secrets(text, current, supplied=None, is_json=False)

Returns a tuple: the filled text, the count of placeholders resolved, and a list of unresolved placeholders.

  • Placeholders look like <redacted:xxxxxxxx>. Each one is filled from supplied when given, otherwise from the value at the same spot in current (the file already on disk), matched by section and line shape.
  • A placeholder with no value is returned in the unresolved list. Comment lines (starting with ; or #) are not reported.
  • is_json=True walks the parsed JSON instead of the lines and returns the JSON text, pretty-printed with sorted keys.

3.3http_get(url, max_bytes, timeout=20)

Returns the response bytes. Only https:// addresses are allowed; anything else raises ValueError. The request sends the User-Agent asl-dvs. A response larger than max_bytes raises ValueError rather than being cut short.

Part 4 · Firewall

Opening and closing ports

The three firewall helpers share one pattern. They look at the firewall that is actually running, change it only when needed, and report what happened with a short code.

4.1firewall_backend()

Returns "firewalld" when firewall-cmd --state says running, "ufw" when ufw status verbose says active, otherwise "none". firewalld is checked first. Missing commands and timeouts count as "none".

4.2open_firewall_port(port, proto="tcp") and close_firewall_port(port, proto="tcp")

Returns a tuple: a code and a message.

CodeMeaning in openMeaning in close
+Port opened (firewalld: now and after a reboot)(not used)
-(not used)Port closed
=Already open, or no firewall runningWas not open, or no firewall running
!Could not open the portCould not close the port, or ufw's default still allows incoming traffic
  • firewalld: open treats the port as open if the zone target is ACCEPT or the port is listed. It adds the port both now and permanently. Close removes it both ways and checks again.
  • ufw: open looks for an ALLOW rule or the default-allow setting, then runs ufw allow. Close runs ufw --force delete allow and warns when the default still allows incoming traffic.
  • With no firewall running, both functions change nothing and return "=".
Part 5 · Asterisk, system and logs

Asterisk, system profile and the suitelog

5.1ami_credentials(conf_path, user="", secret="")

Returns a (user, secret) pair. If both are given they are returned unchanged. Otherwise the function reads the Asterisk manager file and returns the first section, other than [general], that has a secret. Returns ("", "") when nothing is found. Only Node Talker uses it.

5.2allmon3_sync(text, add=(), remove=(), own="")

Returns the new allmon3.ini text and a list of notes.

  • Removes the sections named in remove.
  • Adds the sections named in add (in numeric order). Each new section copies its host, port, user and pass lines from a public node section. Public sections are numbered outside 1000 to 1999, and the own node is preferred.
  • If there is no public section to copy from, nothing is added and a note asks for a manual change.

5.3system_profile(root="/")

Returns a dictionary: board (pi or other), model, os_id, os_name, codename, version_id, arch, wifi_manager (NetworkManager, wpa_supplicant, systemd-networkd or unknown), wifi_iface, and wifi_ifaces. The root argument lets a test point the function at a copy of the filesystem.

Part 6 · Reading the sheet

Points for the book

6.1Single-user functions

ami_credentials is used only by Node Talker, and http_get only by 44helper.

6.2Full build and pi02w

The firewall functions are listed for the pi02w tools and the shared tools only. The full-build Node Controller and SysMon do not carry them. Any change to a firewall function therefore has to be copied into the pi02w tools, and the full build is unaffected unless it is listed.

6.3Return conventions

  • Firewall helpers return a code and a message. The codes are +, -, = and !.
  • Writers return True or False. atomic_write returns False only when skip_same found nothing to change.
  • fill_secrets and allmon3_sync return the new text along with what they resolved or noted, so the caller decides what to show.

6.4How this sheet was made

Read from the source files in the repository on branch ccr-9d4fe19f-ssud83. The sheet describes the code as it stands. It was not written from the tools' manuals.
