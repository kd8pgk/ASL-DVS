Part 3 · The link commands

The Asterisk link codes

Each link command is sent as rpt cmd <local node> ilink <code> <node>. The code names the operation.

CodeUsed byMeaning as used here
1_disconnectDisconnect one link.
2_connect for phone listen-only nodesConnect receive-only (listen).
3_connect (the normal case); the Node Talker transmit node after a fallbackConnect two-way (transceive).
6_ilink6_pair, the fallback when the link list cannot be readDisconnect all links. Sent twice, 0.2 s apart.
11_disconnect_permDrop a permanent link (one listed in rpt.conf under nodes=). The log messages say "permanent link ... ilink 11".

The code does not comment on the codes. The meanings above come from how the code uses them and from its log messages. Check them against the Asterisk app_rpt documentation for the installed version before publishing.

Part 4 · Connect flows

Making a link

4.1ASL and connect by number

Entry: action_asl_connect (7255) and action_connect_by_number (7249), both calling _do_asl_connect (7339).

  1. Check that the node is all digits. Refuse a bridge node.
  2. Take the link lock and reset the permanent-link settle timer.
  3. Drop every other link (_drop_links, keep none).
  4. Connect the node with code 3, or code 2 for a phone listen-only node.
  5. Wait 1.5 s, arm the bridge reaper, and set the page to ASL with the node as the current favorite.

4.2EchoLink

Entry: action_echo_connect and action_echo_connect_by_number, through _do_echo_connect (7391). The same steps as ASL, with the node mapped to its ASL number first. A by-number EchoLink node may have at most seven digits. The page is set to ECHO.

4.3D-STAR and XLX

Entry: action_dstar_connect and action_xlx_connect, through _do_dstar_family_connect (7142).

  1. Check the reflector or gateway callsign, the module letter and the length. A gateway callsign is 3 to 6 letters or digits. A reflector is REF, XRF or DCS plus three digits. XLX takes a single-letter module.
  2. Clear any other link (_clear_foreign_link).
  3. Send the D-STAR unlink and the talkgroup disconnect, then wait the settle time (400 ms).
  4. On ASL, connect the digital bridge node if it is not already linked.
  5. Set the mode to D-STAR, then wait out the rest of the settle time.
  6. For a gateway with ircDDB remote control configured, link through remote control and tune to CQCQCQ. If that fails, fall back to a plain tune.
  7. Tune dvswitch.sh to the reflector or gateway. A timeout returns a message saying the tune may still be completing, and the page state is not updated.

4.4M17

Entry: action_m17_connect (7275), which also takes the lock.

  1. Check the reflector IP, the base name and the module (A to Z, or @ALL). Refuse if the M17 bridge is not detected.
  2. Clear any other link, and send the talkgroup disconnect.
  3. Write USRP2M17.ini for the reflector and restart the M17 service.
  4. On ASL, connect the M17 bridge node if it is not already linked.
  5. Set the page to M17, with the favorite as base|module.

4.5Local API (Node Talker)

Node Talker sends connect to action_local (14521). That switches to the ASL or ECHO tab when needed and then calls the same ASL or EchoLink connect as the dashboard. An M17 link from Node Talker goes through _local_m17_connect (14708), which checks the reflector against the host list or the M17 favorites and the modules it publishes.

Part 6 · Drop-all, reset and boot

Clearing everything

6.1Dropping every link: _drop_links

Used by ASL and EchoLink connects, by the boot disconnect, and by the emergency reset. The steps are:

  1. Read the linked nodes with rpt show variables. If the read fails, send code 6 twice (0.2 s apart), restore the Node Talker transmit link with code 3 on node 1921 if that link is owned and running, and log what is still linked.
  2. Otherwise, for each linked node except the one to keep and the Node Talker listen set: code 11 if the node is a permanent link, otherwise code 1.
  3. Stop after 16 links per pass. The poller handles the rest.
  4. Pause 0.25 s between nodes.
  5. After 1 s, a background check logs any link still up. It does not retry.

_disconnect_all (4339) is this call with nothing to keep.

6.2Emergency reset: action_disconnect_all

The dashboard's reset (7656). It holds the link lock and then:

  1. Graceful step (_graceful_notify, 7633): send the D-STAR unlink if the page is D-STAR or XLX, send the talkgroup disconnect, and, when ASL is present, drop every link.
  2. Restart step (_hard_restart_stack, 7642): restart the analog bridge and the MMDVM bridge, and Asterisk if ASL is present. Wait 2 s, then set the current digital mode again (FCS becomes YSF).
  3. Clear the favorites and linked node in the state, and set the status to the page with RESET.

This is the only disconnect path that restarts Asterisk. It interrupts every link, including the Node Talker path, and the bridge services.

6.3Boot

  • A process restart within the same boot keeps live links. The code logs this and does not disconnect.
  • On a fresh boot with ASL present, _asl_boot_disconnect (15106) waits up to 450 s from dashboard start, for Asterisk to have been up for 30 s and for the network to be ready. It then runs _disconnect_all.
  • If Asterisk is not up after the wait, the boot disconnect is skipped and logged.
  • When the disconnect finishes, the boot ID is written to /run/asl_dvs/boot_disconnect_done. A later process start in the same boot does not repeat it.
Part 7 · Locks and bridge slots

Keeping actions in order

7.1One lock for link actions

  • All link actions share one reentrant lock, _link_action_lock. It is taken by _link_enter and _link_guard, and by the @_link_locked decorator.
  • @_link_locked waits up to 2 s for the lock. If it still cannot get it, the action is refused with "Busy — another connect, disconnect or tab switch is still running."
  • Checked for this review: every connect and disconnect entry point takes the lock, either directly or through a decorator. The two wrappers without a decorator, action_dstar_connect and action_xlx_connect, only call a locked function. action_m17_disconnect takes the lock itself before calling its locked core.
  • _is_connecting() reports whether a link action is running. The page can use it to show progress.
  • The bridge reaper (Section 7.2) tries the lock without waiting and skips its pass if the lock is busy.

7.2Bridge slots are owned by the dashboard

  • The digital, M17 and phone bridge nodes are bridge slots. ASL and EchoLink connects refuse them, and so does the Node Talker local API.
  • The bridge reaper is armed by the first connect. A bridge node that stays linked for two polls, and is not the node the current tab owns, is dropped. Each node has an 8 s cooldown after a drop.
  • _clear_foreign_link (6957) drops the linked node unless there is none, it is node 0, it is a bridge node, or it is the current favorite. It drops with code 11 if the node is permanent.
Part 8 · Points to decide on

Things the review found

These are observations from reading the code. They are not bugs that were tested. The book author can decide which to describe as design and which to flag.

8.1"Connected" means the command was sent

_asterisk (4178) logs a warning when Asterisk refuses a command, but returns nothing. So _connect, and every connect action built on it, returns success whatever Asterisk did. The page state shows the link as set. The poller and rpt show variables are the only later checks on whether the link came up.

8.2Link drops are capped

One pass of _drop_links drops at most 16 links. Any others are left to the poller. That is fine for normal use but worth knowing if a node is ever linked to many nodes at once.

8.3The fallback does not check permanent links

When the link list cannot be read, _drop_links sends code 6 twice without first checking the permanent-link list. Code 11 is used only when the list is read. The fallback then restores only the Node Talker transmit link.

8.4The emergency reset restarts services

action_disconnect_all restarts Asterisk and both bridge services. It is the only disconnect path that does, so it is much more disruptive than the others. Node Talker and every tab lose their links until the services are back.

8.5Failed tunes do not update the page

When a D-STAR or XLX tune times out, the action returns a message saying the tune may still be completing, and does not update the page state. The bridge can then be on a new reflector while the page still shows the old one. The message tells the operator to check the tab before retrying.

8.6The teardown check only logs

After a drop, the background check logs links it still sees and does not retry them. A link that survives is found only in the log.

8.7Meanings of the link codes

The codes in Part 3 are not commented in the source. Confirm them against the installed Asterisk version before the book states them as fact.
