Node Listen Manual
Receive and transmit audio, setting by setting

Node Listen puts one node in your phone's browser: listen with about half a second of delay, talk with push-to-talk, and connect favorites. This manual follows the audio both ways, from the radio to your ear and from your mic to the air, and explains every setting along the way: where it acts, what it does, when to change it, and how to measure the result with the built-in meters, tests and Audio check.

How to read it

If you only want to listen, chapters 2 and 3 are enough. If you transmit, read chapters 5 and 7 before your first contact: most audio complaints come from levels that were never set. Chapter 6 is the reference to come back to. Each setting is marked with where it is kept:

MarkMeaning
NODEKept on the Pi in /etc/asl_dvs/nodelisten.conf. Changes it for everyone who uses Node Listen on this node. Needs you to be logged in.
BROWSERKept in this browser only. Each phone, tablet or computer has its own, and changing it on one leaves the others alone. No login needed.
NOTELevels are given in dBFS: decibels below digital full scale. 0 dBFS is the loudest a sample can be; −6 dBFS is half that; −20 dBFS is a tenth. Speech is measured as an average (what you hear as loudness) and as a peak (the loudest instant, which is what clips).

Chapter 1

What Node Listen is

A web page served by the Pi on port 8993 that lets a phone, tablet or computer listen to one node, transmit through it, and connect a short list of favorites. There is no app to install.

Receive

The node's audio, about half a second behind, cleaned up on the Pi (CTCSS and hum cut, levels evened out, squelch tails muted) and played in the browser with a live spectrum.

Transmit

Push-to-talk from the phone's microphone, processed in the page (filter, leveler, noise gate) and sent to a private node, 1921, that Node Listen keeps linked to your node.

Connect

Up to 10 favorites: AllStar nodes, EchoLink stations and M17 reflectors. Node Listen reports whether each link actually came up.

Measure

Live meters, a mic test, a test through the node, and an Audio check that watches a few minutes of real use and says what to change.

1.1What it needs

ItemWhy
An ASL3 node (Asterisk with app_rpt)Node Listen takes the node's audio from Asterisk and transmits through it.
Python 3.11 or laterAs on Debian 12 and 13. Node Listen uses only the standard library.
A modern browserChrome, Firefox, Safari or Edge from the last few years. The microphone needs the https:// page.
Optional: the Dashboard (Node Controller)Needed for M17 favorites; when it runs, connects from its node go through it so it shows them.

1.2How it fits on the node

Node Listen adds two things to /etc/asterisk/rpt.conf, each with a backup first: one outstreamcmd line in your node's stanza, which sends the node's audio to Node Listen, and a private node 1921, which carries your transmissions in. Everything else stays as it was: the radio, the other links and DVSwitch hear and send exactly what they did before.

Chapter 2

Install and first setup

Ten minutes from nothing to a first test transmission.

2.1Install

  1. The installer (7.2.0 and later) asks whether to add Node Listen; instmon (2.58.0 and later) lists it with the other tools and updates it. By hand: sudo python3 nodelisten_v….py --install.
  2. Open http://<pi-address>:8993. Node Listen moves you to https://. The certificate is made on the Pi, so the browser warns once: accept it.
  3. Log in with the Pi's root password.

2.2Receive: send the node's audio here

  1. Setup tab, open the Receive card. The table lists each node in rpt.conf and its outstreamcmd, if any.
  2. Pick your node and press Send its audio here. That node becomes Node Listen's main node.
  3. Press Restart Asterisk (it asks first; every link drops and reconnects).
  4. Listen tab: within a few seconds the status line shows a green feed light, and audio plays when the node passes any.
CAREFULA node takes one outstreamcmd. If yours already has one (a Broadcastify feed, for example), Node Listen refuses rather than replace it.

2.3Transmit: add node 1921

  1. Setup tab, open the Transmit card and press Add node 1921. Node Listen adds a [1921] stanza (your node's template, a USRP channel, no hang time, telemetry or courtesy tone) and a [nodes] line, after a backup.
  2. Press Restart Asterisk. Within 20 seconds the card's summary reads Set up and linked: Node Listen links 1921 to your node and relinks it whenever it drops.

2.4First test transmission

  1. Setup tab, Microphone card: press Test mic, talk for 4 seconds, and read the report (section 8.2). Adjust Mic gain until it says Good.
  2. Press Test through the node. It transmits for 4 seconds, over the air and to every link, and plays back what the node sent out.
  3. Listen tab: hold the push-to-talk button and make a short call.

Chapter 4 · RX

Receive (RX) audio

From the radio to your ear: everything the node hears, cleaned up once on the Pi for every listener, then buffered, played and drawn by each phone.

4.1From the node to Node Listen

app_rpt mixes everything your node hears (the radio, every link, telemetry) and writes it, 8,000 samples a second at 16 bits, to the outstreamcmd program, a small part of Node Listen that passes it on to 127.0.0.1:6200. The audio pump cuts it into 20 ms frames (160 samples) and sends one to every listener every 20 ms. If audio arrives in bursts, up to 0.5 s waits in a queue; beyond that the oldest is dropped and counted.

The status line's feed light is green while frames arrive. The RX light and the busy lockout use the node's own level before any cleanup: a frame louder than −50 dBFS counts as audio, held for 0.6 s.

4.2RX cleanup on the Pi

Three steps, done once for every listener, change only what Node Listen's listeners hear. They are on by default; chapter 6 has each setting in detail. Nothing is done while nobody listens, and near-silent frames (under −65 dBFS) skip the work.

StepWhat it does to the sound
Cut below 300 HzRemoves hum and the lower CTCSS (PL) tones: 100 Hz drops by about 38 dB, 150 Hz by 24 dB, 250 Hz by 7 dB. Voice above 300 Hz is untouched.
Automatic levelAims speech at about −20 dBFS: brings quiet stations up by as much as 18 dB and loud ones down by as much as 6 dB. It turns down within a frame or two, comes up at 3 dB a second (faster for the first half second of a new transmission), and holds still between transmissions. RX gain (Audio levels) is added on top.
Soft limiterUp to about −1 dBFS nothing changes; above that, peaks are rounded off smoothly instead of clipped.
Squelch-tail gateMutes the burst of hiss after a station unkeys, and long silences. It tells hiss from voice by how alike neighbouring samples are: voice scores high, hiss low. To mute a tail from its first frame, it holds the audio back 80 ms.

4.3To your phone and out of the speaker

  • Format: 16-bit (128 kbit/s) by default, or μ-law (64 kbit/s) with 16-bit audio off. μ-law is the phone-line format: half the data, a little more hiss on quiet audio.
  • Listen buffer: the page plays each 100 ms of audio a fixed time after it arrives, 0.25 s by default, so a late packet doesn't make a gap. When audio arrives later than the buffer can cover, playback restarts (a dropout), and the Audio check counts it.
  • Smooth playback: the page upsamples 8 kHz to the phone's own rate (44.1 or 48 kHz) with a proper filter, which removes the faint sizzle some phones add.
  • Volume and then the speaker. The spectrum and meters see the audio before the volume.

4.4Where the half second goes

StageDelay
Asterisk to Node Listena few tens of ms
Squelch-tail gate look-ahead80 ms (only with the gate on)
Page chunksup to 100 ms
Listen buffer250 ms by default (150 ms to 1 s)
Networka few ms on Wi-Fi at home; more on mobile data

The total is about half a second at home. This is why the node's own audio comes back late when you test through it, and why Node Listen ignores the busy lockout for 1 s after your own transmission.

Chapter 5 · TX

Transmit (TX) audio

From your mic to the air: shaped in the page, sent in 20 ms pieces, smoothed on the Pi and fed to node 1921, which is linked to your node.

5.1In the browser

  1. Browser processing. The phone's own Automatic gain, Noise suppression and Echo cancellation, each switchable. They run before Node Listen sees the sound.
  2. Mic gain, −12 to +24 dB: a plain volume control on the mic.
  3. Resample to 8 kHz with a filter that cuts at 3.4 kHz, so sounds above it don't fold back as hiss or whine.
  4. Voice filter (cuts rumble below about 250 Hz) or Radio voice (cuts below 300 Hz and lifts 2.5 kHz by 4 dB, a crisper, more "radio" sound). With Radio voice on, the voice filter is skipped.
  5. Noise gate (Off, Light, Strong): turns the mic down between words.
  6. Leveler: a gentle compressor that keeps your level even, followed by a limiter that never lets a peak past −1 dBFS.
  7. Every 20 ms (160 samples) a frame goes to the Pi over the WebSocket /api/talk.

5.2On the Pi and on the air

  1. TX buffer. The Pi waits until it has this much of your audio (120 ms by default) before it starts sending, so short hiccups on the phone's connection don't make gaps. If it runs dry anyway, it sends silence, refills, and counts a gap.
  2. TX gain (−12 to +12 dB, with a soft limit at about −1 dBFS), only with Adjust audio levels here on.
  3. The frames go as USRP packets to node 1921 (127.0.0.1:32018), keyed. On release the last frame is faded out and three unkey packets follow.
  4. Node 1921 is linked to your node, so your audio goes out on the radio and to every link, like a local user's.

5.3The safety rules

RuleWhat happens
Busy lockoutWith Don't transmit while the node is busy on, a press is refused while the node passes audio (the RX light), except within 1 s of your own unkey.
One at a timeA second person's press is refused while someone transmits from Node Listen.
Time-outThe transmission stops at TX time-out (120 s by default). Let go and press again.
Audio stoppedIf no audio reaches the Pi for 1 s (a dropped connection), it unkeys.
Page hiddenSwitching apps, locking the phone or leaving the page releases push-to-talk.

Chapter 7

Getting levels right

A short procedure for each direction, in the order that avoids fighting yourself. Do it once when you set the node up and again when you change phones, mics or radios.

7.1Who hears which gain

GainWhereWho it changes
Radio RX / TX levels, DVSwitch gainsSysMon, Tune tab; DVSwitchEveryone: the air, every link, Node Listen.
Automatic level, RX gain, Cut below 300 Hz, gateNode Listen, Audio levels NODENode Listen's listeners only.
TX gainNode Listen, Audio levels NODETransmissions from every Node Listen user.
Mic gain, leveler, filters, gateNode Listen, Microphone BROWSERTransmissions from this device only.
VolumeListen tab BROWSERWhat you hear on this device only.
TIPFix things where they start. If the node's own audio is wrong on the air and on links, fix it in SysMon (radio) first; Node Listen's settings only paper over it for Node Listen's users.

7.2Transmit, step by step

  1. Start clean. Microphone card: Leveler on, Automatic gain off, Noise suppression on, Voice filter on, Noise gate Off, Mic gain 0 dB.
  2. Test mic. Hold the phone where you will hold it on the air and talk normally for 4 seconds. Targets: speech −24 to −12 dBFS, peaks −8 to −1 dBFS, limiter working under 20 % of the time. Change Mic gain by the amount the report suggests and test again until it says Good.
  3. Noise. If the report says Noisy, move to a quieter spot or closer to the mic first; then try Noise gate Light.
  4. Test through the node. For an exact comparison, turn Automatic level off for a minute (Audio levels). Came back should be within about 6 dB of Sent. If every phone comes back quieter or louder by the same amount, use TX gain; if the radio side is off, use SysMon's Tune tab. Turn Automatic level back on.
  5. On the air. Run an Audio check during a real contact or net (section 7.4) and apply what it suggests.

7.3Receive, step by step

  1. The node first. With the radio's own levels right (SysMon, Tune), the RX level on the Audio levels card should peak around −10 to −3 dBFS on a strong local station.
  2. Look at the spectrum. A steady line or band below 300 Hz is a CTCSS tone or hum; with Cut below 300 Hz on it should be faint or gone. Thin bright lines right after transmissions are squelch tails: the gate should remove them.
  3. Leave Automatic level on. If speech is still quiet (the Audio check says so), raise RX gain by the amount it suggests.
  4. Dropouts. If audio breaks up on your connection, raise the Listen buffer a step.

7.4The Audio check

The quick tests show four seconds; the Audio check shows a few minutes of real use, with several stations and several of your own transmissions.

  1. Setup tab, Audio check card: choose a length and press Start check.
  2. Go to the Listen tab and use the node as usual: listen, talk, listen. The status line shows CHECK 2:13; tap it to come back.
  3. When it ends (or you press Stop), open the card. Each row is green, amber or red against its target, and What to change lists suggestions with amounts.
  4. Press Apply on a suggestion to make the change (Undo puts it back), run another check, and press Compare with last check to see the difference.

7.5Common mistakes

  • Two automatic gains. The browser's Automatic gain and the leveler fight; leave the browser's off.
  • Mic gain into the limiter. More mic gain past the point where the limiter works most of the time adds distortion, not loudness. If the report says the limiter works more than 30 % of the time, turn it down.
  • Fixing the radio in Node Listen. RX gain and Automatic level only change Node Listen's listeners; a bad radio level still goes to every link.
  • Radio voice on a bright radio. If the radio adds pre-emphasis, Radio voice makes it shrill.
  • Judging levels through the speaker. Phone volume and speakers vary; trust the meters.
Chapter 8

Reading the spectrum and the meters

The waterfall shows what the node passes, the meters show levels, and the test reports say what to change.

8.1The waterfall

Frequency runs across, 0 to 4 kHz (marks at 300 Hz, 1, 2 and 3 kHz); time runs down, newest at the top, about 25 lines a second. Colour is loudness: dark is quiet, teal is moderate, amber and red are loud. The strip below 300 Hz is shaded. Tap it to switch to bars, which show the same moment as a bar chart. The examples below were made with a synthetic voice on a test node, with each problem added in turn.

8.2The live meter and the mic test report

The bar runs from −60 to 0 dBFS. The teal fill is the average, the amber mark the peak, and the thin white mark the highest peak of the last second. The green zone (−6 to −3 dBFS) is where peaks belong; above −1 dBFS is red. The thin bar underneath shows how far the leveler's limiter is turning you down; the text says limiting 4.2 dB or gate closed.

NumberMeaning
PeakThe loudest instant. Should be −8 to −1 dBFS.
SpeechThe average while you talk. Should be −24 to −12 dBFS.
BackgroundThe quietest tenth of the recording: the room. silent means digital silence.
Voice above backgroundSpeech minus background. Over 20 dB is clean; under 15 dB sounds noisy.
Limiter workingHow much of your speech the limiter was turning down. Over 30 %: too much mic gain.
Gate closed while talkingShown with the noise gate on. Over 10 %: the gate is eating words.

8.3The node test report

The test transmits for 4 seconds through the node and records what the node sends back out. The two strips are lined up so the same words sit above each other; Round trip is how long that took (about half a second at home). Difference compares the speech levels: within about 6 dB is fine.

With Automatic level on, what comes back has been evened out, so the report says so and doesn't judge the difference; turn Automatic level off for a minute to compare exactly.

A came-back peak near 0 dBFS means something on the node's side is clipping: TX gain, or the radio and DVSwitch levels in SysMon.

8.4The level bar while you talk

While you hold push-to-talk, the level bar under the spectrum shows your mic level in red, labelled TX; when you let go it goes back to the node's level. Peaks should reach the green zone of the live meter, about −6 to −3 dBFS, on normal speech.

Chapter 10

Troubleshooting by symptom

Each from the quickest check to the bigger fix. The Log card and SysMon's Node Listen card (its ASL-DVS tab) show what Node Listen and the node are doing.

No audio at all

  1. Status line: no feed yet means Asterisk isn't sending. Receive card: is the line on your node? Send its audio here, then Restart Asterisk.
  2. Feed green but silent: is the RX light on? Is Listen showing Listening.? Check the volume and the phone's own volume.
  3. Tap anywhere to start listening: the browser is holding sound until you tap.
  4. All 3 listener slots are in use: raise Max listeners or wait.

Audio breaks up or stutters

  1. Raise the Listen buffer a step (0.5 s on mobile data).
  2. Turn 16-bit audio off to halve the data.
  3. Move closer to the Wi-Fi access point. The Audio check counts dropouts.

Some stations are much quieter than others

Turn Automatic level on (Audio levels). If one station is quiet everywhere, it is that station.

Low hum or a tone under every transmission

Turn on Cut below 300 Hz. If the waterfall shows hum between transmissions too, it is on the node: check the radio interface's grounding.

A burst of hiss after every transmission

Set the Squelch-tail gate to Light, then Strong. The real fix is the radio's squelch or COS on the node sending it.

My transmissions are too quiet, too loud or distorted

Run the mic test and follow it (section 7.2). Distorted with a lot of limiting: lower Mic gain. Fine in the test but bad on the air: the node test, then TX gain or SysMon's radio levels.

Gaps or choppy audio in my transmissions

Raise the TX buffer to 200 ms; use Wi-Fi rather than mobile data. The Log shows gaps per transmission.

Push-to-talk is refused

MessageFix
The node is busyWait for quiet, or turn off the busy lockout if a constant noise keeps the node busy.
Someone else is transmittingWait; the button shows Busy with who and how long.
Node 1921 is not set up / not linked yetTransmit card: Add node 1921, Restart Asterisk, wait 20 s.
Push-to-talk needs the https:// pageTurn HTTPS on and open the https:// address.
Microphone: Permission deniedAllow the microphone for the page in the browser's site settings.

Transmission stops by itself

Time-out: raise TX time-out. Audio stopped reaching the node: the phone's connection dropped; use Wi-Fi or raise the TX buffer.

Phone-specific

  • iPhone: sound needs one tap after the page opens; the lock screen keeps playing while the page is the active audio. Push-to-talk stops when the screen locks.
  • Android: battery savers may stop audio in the background; allow the browser to run in the background.
  • Bluetooth headsets switch to a low-quality call mode when the microphone opens; expect duller listen audio while you test or talk.
Chapter 11 TESTING

From the internet, and security

Node Listen is meant for your home network. Internet access is off unless you turn it on.

  • allow_wan in /etc/asl_dvs/nodelisten.conf (no checkbox; then sudo systemctl restart nodelisten). Off, clients from the internet get not open to the internet for every page. Home addresses, link-local and Tailscale (100.64.0.0/10) always count as home.
  • A Cloudflare Tunnel or Tailscale Funnel counts as the internet, whatever address it arrives from.
  • From the internet the password is only accepted on the https:// page.
  • On top of the per-address lockout, 20 failed internet logins in 10 minutes make every internet login wait until that window ends. Home logins are never held.
CAREFULThe login is the Pi's root password. Before opening Node Listen to the internet, make sure it is long and used nowhere else, and keep the Dashboard and SysMon on the home network.
